# Phase 4 — LCG mock experiments and reader separation

No Lua, decoder closure or payload executed. No source fetching or network calls.
Artifacts are pinned to the same g/d hashes as previous phases.

## Reproduction

```powershell
python tools/lcg_decoder.py
python tools/state_separator.py
python -m unittest discover -s tools -p "test_*.py" -v
```

Default LCG experiment: three independent 4096-byte windows at offsets 0,4096,
8192. Test all 256 starting states in each window, extra word XOR mask assumed
zero. Keep the three lowest empirical entropy candidates. Generated bytes remain
local in output/phase4/lcg/*.hypothesis.bin; no candidate is marked decrypted.

## Arithmetic model
Reuse mask_tables from decryption_finder.py, with multiplier61/increment123/mod256.
OW packs four successive states little-endian, VW is the fourth state. The word
XOR and sequential byte XOR are equivalent, not two independent validations.
61 has multiplicative inverse21 modulo256, so previous_state=(state-123)*21%256.
This reverses a PRNG state only. Recovering plaintext uses XOR with the same known
keystream; inverse LCG does not locate records, determine starting state or remove
an unknown extra mask.

The observed zW XOR uses another mask as well. Experiments assume it is zero
(or the explicit --word-mask value); the state schedule and record boundaries
are still unresolved. Window starts are not asserted to be record starts.

## Results
All entropy values are measured on equal 4096-byte windows, not compared with
whole-file entropy 7.999308. Ranking is by minimum entropy, NOT best verified text.

| 0 | 7.513396 | 7.937451 | 9 | 41.28% |
| 4096 | 7.951787 | 7.459914 | 9 | 62.79% |
| 8192 | 7.958400 | 7.320235 | 9 | 64.55% |

The first window gets less structured by this entropy metric. Later windows
show a substantial change, but no validated constant/prototype record has been
parsed and no listed top candidate begins with a recognized compression/file
signature. Printable runs do not establish meaningful recovered strings.

Seed137 has exactly the same entropy as seed9: starting states that differ by128
produce keystreams differing by constant XOR0x80. A fixed byte XOR permutes byte
histogram labels and preserves entropy. Thus entropy cannot uniquely identify
the seed, and the matching seed ranking across windows is not proof of decoding.

Controls: applying fixed XOR0xA5 preserves input entropy. One deterministic random
sample per window is passed through the same 256-seed search; minimum entropies
are approximately7.946878,7.942431,7.941869. This is a negative-control example,
not a calibrated significance test or a false-positive probability. Searching
many seeds introduces selection bias; do not accept the minimum unconditionally.

## Separation
state_separator.py extracts 11 exact hash-pinned source regions as VIEW-ONLY
text, trimming only the reviewed trailing scalar-alias syntax. Source offsets
and region hashes are in separation-report.json. This is lexical extraction,
not a complete AST, dependency closure, control-flow reconstruction or executable
standalone decoder.

sW-before-v.view.txt replaces the original combined parse-and-invoke expression
with a descriptor BEFORE calling v. Neither v nor the returned closure is called.
This view deliberately changes semantics and must not be executed. Original
reader excerpts still contain lazy functions and unresolved dependencies; they
are not a safe runtime adapter. No original g source is modified.

reader-flow.mmd is a normalized sequence overview, not a verified runtime CFG.
The operation list documents allocation, byte slice copy, cursor update, parsing
and the subsequent closure invocation; all are observations, not performed work.

## Next steps, in order
1. Derive actual cursor, seed and additional XOR mask at a specific reader branch
   from CW/GW/v state assignments. Keep record offsets tied to source evidence.
2. Translate that bounded reader branch to Python and validate its outputs and
   exact bytes consumed. Test with synthetic fixtures and independent expectations.
3. Verify repeated record tags, bounded lengths, counts, references and total bytes
   consumed before naming sections constant/prototype/instruction tables.
4. If source-derived output carries a compression signature, test the identified
   decompressor with bounded output and a complete-stream check. A random two-byte
   zlib-looking header alone is not evidence. Do not guess a second cipher based
   solely on remaining high entropy.
5. Validate findings against separate untouched records/windows; only then call
   the output decoded and proceed to opcode mapping.
